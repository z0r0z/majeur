## Below Confidence Threshold

[75] **1. Intermediate truncation in `_cost` underprices buyers near curve exhaustion**

`ClassicalCurveSale._cost` · Confidence: 75

**Description**
`_cost()` computes the XYK integral in two chained `mulDiv` steps: `step = mulDiv(P₀·N, T₀, rem)` (floor) then `mulDivUp(step, T₀, remAfter·1e18)`. The intermediate floor truncation in `step` is magnified by `T₀/(remAfter·1e18)` in the second step, causing a buyer-favorable undercharge of up to `ceil(T₀/(remAfter·1e18))` wei per trade. For realistic curves (T₀ ~ 1e24), the error is dust-level (~1 wei). For extreme parameters (T₀ ≈ uint128.max, remAfter = 1), the discount could theoretically reach ~340 ETH — but this requires pathological curve configuration with maximum virtual reserve and a single token remaining.

[75] **2. `sellExactOut` blocked for curves with feeBps=10000**

`ClassicalCurveSale.sellExactOut` · Confidence: 75

**Description**
`_configure()` validates `feeBps > 10_000` (strictly greater), allowing `feeBps = 10_000` as a valid configuration. The `sell()` function handles this correctly (net proceeds = 0). However, `sellExactOut()` adds an extra guard `if (feeBps >= 10_000) revert InvalidParams()` at line 809 that no other sell path checks, permanently bricking `sellExactOut()` for 100% fee curves while `sell()` remains functional — an inconsistent interface.

[75] **3. ZAMM first-mint exact consumption assumption unasserted**

`ClassicalCurveSale.graduate` · Confidence: 75

**Description**
`graduate()` pre-computes `excessETH = c.raisedETH - ethForLP` before calling `ZAMM.addLiquidity()`. The code comment asserts ZAMM first-mint (supply=0) consumes exact desired amounts, but no on-chain assertion verifies `used0 == ethForLP`. If ZAMM's behavior ever deviates (upgrade, rounding), any refunded ETH lands in the contract's `receive()` fallback and accumulates permanently with no recovery path.

[75] **4. Hardcoded zrouter perpetual allowance exemption**

`ERC20.transferFrom` · Confidence: 75

**Description**
The ERC20 clone's `transferFrom` exempts three hardcoded addresses from allowance checks: `hook` (this contract), `zamm`, and `zrouter`. While the first two are tightly coupled to this contract's operations, `zrouter` is an externally controlled router whose security boundary extends beyond this contract. If zrouter is ever compromised or has a vulnerability permitting arbitrary `transferFrom` calls, all holders of all tokens launched via `launch()` can be drained without approval.

---

[75] **5. Integer sqrt rounding in virtual reserve computation**

`ClassicalCurveSale._configure` · Confidence: 75

**Description**
The virtual reserve `T₀ = cap · √endPrice / (√endPrice − √startPrice)` uses floor-truncated integer square roots. The truncation error propagates to T₀, meaning `price(cap)` does not exactly equal `endPrice`. For curves where `√endPrice − √startPrice` is small (prices close together), the deviation can be meaningful — no on-chain assertion enforces the `price(cap) == endPrice` invariant. Impact is symmetric across all participants.

## Leads

_Vulnerability trails with concrete code smells where the full exploit path could not be completed in one analysis pass. These are not false positives — they are high-signal leads for manual review. Not scored._

- **`graduate()` stale storage re-read in no-pool early-exit** — `ClassicalCurveSale.graduate` L934 — Code smells: uses `c.raisedETH` (fresh storage read) instead of cached `ethForLP` local — Currently no divergence in reachable paths (both values are identical), but a latent inconsistency if future refactors modify `ethForLP` before the `tokensForLP == 0` branch. Recommend using `ethForLP` for consistency.

- **`buyExactIn` correction loop unbounded** — `ClassicalCurveSale.buyExactIn` L702-709 — Code smells: while loop decrements `amount` by 1 per iteration with a full `_cost()` recomputation — The algebraic inverse is exact for XYK (0–2 iterations typical), but for pathological near-zero-price configurations, the overshoot could be large. Self-DoS only (caller bears gas). No profitable attack vector.
